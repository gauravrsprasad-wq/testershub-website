Our API testing framework

API tests are the fastest and most stable tests you can have. Our framework keeps them organised and runs them on every change.

LayerWhat it does
Test designPositive, negative and edge-case tests for every endpoint, grouped by feature.
Request specsBase URLs, headers and authentication are set up once and reused by every test.
Schema validationEvery response is checked against a JSON schema or OpenAPI contract, so breaking changes are caught.
Test dataData is created through the API before a test and cleaned up after, so runs never depend on each other.
Security checksTests for broken authentication, access to other users' data, and missing rate limits.
Performancek6 load tests with pass or fail thresholds, for example 95% of requests under 500 ms.
CI/CD and reportsNewman or Maven runs in your pipeline and produces an HTML report for every run.

What a test looks like

An example in Java with REST Assured and TestNG:

Example: OrdersApiTest.java (REST Assured)

@Test
public void creatingAnOrderReturnsTheNewOrder() {
    given()
        .spec(authenticatedUser())
        .body(Orders.validOrder("SKU-1042", 2))
    .when()
        .post("/orders")
    .then()
        .statusCode(201)
        .body(matchesJsonSchemaInClasspath("schemas/order.json"))
        .body("items[0].sku", equalTo("SKU-1042"))
        .body("items[0].quantity", equalTo(2));
}

@Test
public void usersCannotReadSomeoneElsesOrder() {
    given().spec(authenticatedUser())
    .when().get("/orders/{id}", Orders.belongingToAnotherUser())
    .then().statusCode(403);
}
